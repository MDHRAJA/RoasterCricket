# IPL analytics backend — version 0.5

The backend is a **read-only FastAPI API over the saved SQLite dataset**. It serves observations, metadata, descriptive analytics, Bayesian delivery forecasts, experimental two-innings simulations and constrained XI/bowling-plan optimization. See the [match-planning guide](match-planning.md) for computation contracts, solver scope and limits. `production_validated_predictions` and `verified_match_eligibility` remain false. See the [model card](bayesian-model.md) for delivery-level backtesting.

## Start locally

The project virtual environment is already prepared. From the project folder:

```powershell
.\scripts\start_backend.ps1
```

Alternatively:

```powershell
.\.venv\Scripts\python.exe -m backend
```

Open [interactive API documentation](http://127.0.0.1:8000/docs). The machine-readable contract is at [OpenAPI](http://127.0.0.1:8000/openapi.json). Stop with Ctrl+C. If the port is occupied, use `-Port 8001` with the script, or `--port 8001` with Python. Do not stop an unrelated application to free the port.

For a fresh checkout with the dataset available, use Python 3.12 or newer:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-backend.txt
```

The pinned runtime dependencies are separate from the data-collection dependencies. Lightweight analytics use SQL without Pandas. Planning requests load their bounded four-year delivery window once and cache sufficient statistics. `pyproject.toml` describes the package; use the pinned requirements for the tested environment.

## Configuration and deployment boundary

`.env.example` documents process environment variables; the application does **not** automatically load `.env` files.

| Variable | Default | Meaning |
| --- | --- | --- |
| `IPL_DATA_DIR` | `outputs/ipl-data` | Dataset folder; relative paths resolve against the project, not the shell's working directory. |
| `IPL_CORS_ORIGINS` | `http://localhost:5173,http://localhost:3000` | Explicit allowed frontend origins, comma-separated. Wildcard origins are rejected. |
| `IPL_QUERY_TIMEOUT_SECONDS` | `5` | SQLite progress-handler budget per connection; must be greater than zero and at most 30. |

The launcher binds only to `127.0.0.1`. This is a local development backend, not a public production service. Public hosting still requires authentication/access decisions, rate limits, HTTPS, monitoring, deployment configuration and a review of third-party data rights. CORS is a browser permission mechanism, not authentication.

Each data request gets a separate connection opened with SQLite `mode=ro` and `query_only=ON`. There are no API write endpoints. Startup checks the required tables, catalogued columns, supported schema version and snapshot metadata. Missing data fails startup without creating an empty database. The progress handler interrupts long-running SQL; it is not a complete HTTP request deadline.

## API contract

All data routes below have the `/api/v1` prefix. `/health` reports process liveness; `/ready` checks that a fresh database connection can read the dataset. `/docs` and `/openapi.json` are generated by FastAPI.

| Route | Purpose / key parameters |
| --- | --- |
| `GET /metadata` | Coverage, conventions, warnings and honest capability flags. |
| `GET /datasets` | All 31 saved dataset catalog entries, provenance-related metadata and hashes. |
| `GET /seasons` | Coverage by collected IPL season. |
| `GET /teams` | Current franchises; `current_only=false` includes historical teams. |
| `GET /teams/{id}/roster` | Official website snapshot; required `season`. |
| `GET /teams/{id}/observed-roster` | Players involved in recorded matches; required `season`, optional `before`. |
| `GET /players` | Search/pagination; `q`, `role`, `hand`, `limit`, `offset`. |
| `GET /players/{id}` | Profile, source references and missing/conflicting attribute markers. |
| `GET /players/{id}/attributes` | Field-level attribute provenance. |
| `GET /players/{id}/statistics` | Aggregate batting/bowling statistics; `season`, `before`, `venue_id`. |
| `GET /players/{id}/form` | Last actual batting/bowling innings; `window=5` or `10`, `before`, `timeline_limit`. |
| `GET /players/{id}/phases` | Powerplay/middle/death splits; `side`, `season`, `before`, `venue_id`. |
| `GET /analytics/matchup` | Required `batter_id`, `bowler_id`; optional `season`, `before`, `phase`, `venue_id`. |
| `GET /analytics/bowling-type` | Required `batter_id`, `category`; optional `arm`, `season`, `before`, `phase`, `venue_id`. |
| `GET /matches` | Pagination; `season`, `before`, `venue_id`, `team_id`. |
| `GET /matches/{id}` | Match, innings, listed participants and recorded replacements. |
| `GET /venues` | Canonical venues. |
| `GET /venues/{id}/profile` | Venue scoring environment and aliases; `season`, `before`. |
| `GET /venues/{id}/phases` | Venue phase splits; `season`, `before`. |
| `GET /predictions/matchup` | Next-legal-delivery posterior; required `batter_id`, `bowler_id`, exclusive `as_of`; optional `phase`, `venue_id`, `curves`. |
| `GET /predictions/bowling-type` | Type-conditioned posterior; required `batter_id`, `category`, exclusive `as_of`; optional `arm`, `phase`, `venue_id`, `curves`. |
| `POST /simulations/match` | Explicit two-team plans, venue, exclusive `as_of`, seeded 50-1000 trials. |
| `POST /optimization/xi` | Candidate pool, opponent plan, locks/exclusions, seeded candidate comparison. |
| `GET /rules` | 2026 core planning profile and outstanding supplementary verification. |
| `GET /predictions/match-benchmark` | Chronological outcome/first-innings benchmarks; required `team_a_id`, `team_b_id`, `venue_id`, exclusive `as_of`. |

Most responses are `{ "data": ..., "meta": ... }`. Paginated lists are `{ "items": [...], "total": ..., "limit": ..., "offset": ..., "meta": ... }`. Metadata includes `dataset_version`, an exclusive `before` cutoff when supplied, and machine-readable warning codes. The frontend should translate relevant warnings into plain-language labels, not hide them.

Page sizes are bounded to 1–100 and offsets to 0–100,000. Results have deterministic ordering. Player IDs are strings, including stable local identifiers such as `ipl:...`; preserve them without numeric conversion. Player search uses literal substring matching plus normalized aliases; ambiguous aliases may return more than one player. Missing attributes and undefined rates are JSON `null`, not invented facts or a zero ability rating.

Error responses use `{ "error": { "code": ..., "message": ..., "details": ... } }`: 404 for unknown entities, 422 for invalid or infeasible plans, 429 when the per-process planning slot is busy, 503 for unavailable data/computation budgets, and a generic 500 for unexpected failures. Responses do not expose database paths or SQL. POST is supported only for the two computation routes; PUT/DELETE and dataset mutations remain unsupported. Local frontend CORS permits GET/POST with JSON content types.

## Analytics conventions and reliability boundaries

### Historical cutoff

`before=2026-04-01` includes only `match_date < 2026-04-01`. Every match on April 1 is excluded because the archive does not provide a sufficiently precise ordering for same-day forecasting. Statistics and form are recomputed from filtered match/delivery records rather than a complete-season aggregate.

This prevents future **performance** records from entering these summaries, but it does not make the entire dataset suitable for leakage-free backtesting. Present-day profile attributes and current website rosters are not time-versioned historical records. The API labels that limitation. Registered roster membership, availability and rule constraints must be reconstructed at the prediction date before testing an optimizer.

### Cricket metrics

Ordinary performance analytics exclude Super Overs. The API uses the prepared dataset's documented flags: legal balls exclude wides/no-balls; recorded balls faced exclude wides and include no-balls. This is a declared derived convention, not a claim of exact official scorecard adjudication/dead-ball handling. Strike rate is `100 * batter runs / balls faced`; economy is `6 * bowler runs conceded / legal balls`. Conceded runs exclude byes/leg-byes/penalty extras according to the data pipeline. Overs notation is not a decimal number.

Matchup outcomes are grouped observed delivery counts, including illegal-delivery records, with legal-ball and balls-faced counts alongside them. These groups are **not** forecast probabilities. Striker dismissals and bowler-credited wickets are distinct; non-striker dismissals do not become striker wickets. Boundary-ball rate divides recorded batter fours/sixes by balls faced; bowling-dot rate divides the prepared legal zero-team-run flags by legal balls.

Phase labels use the data pack's fixed 20-over boundaries: powerplay overs 1–6, middle 7–16, death 17–20. They are not rescaled to rain-shortened playing conditions. The venue profile includes recorded shortened/no-result innings and is an observed scoring environment, not a measured pitch report.

### Recent form

Batting and bowling windows independently take the last 5 or 10 **actual innings**. A DNB appearance is retained in the chart timeline but excluded from batting form. A genuine zero-faced batting innings remains an innings. The timeline is returned oldest-to-newest and defaults to the last 20 appearances.

The summary includes aggregate strike rate/economy, mean runs per innings, a recency-weighted run mean and a linear runs-per-innings trend when at least three batting innings exist. Recency weights decay by `0.85` per older innings; this is an explicitly unfitted descriptive heuristic, not a validated model. Small windows and no-history players retain missing-rate values. A “fewer than 30 balls faced” matchup warning is a display heuristic, not a statistical confidence guarantee.

### Squads and availability

Official squad pages can include replacements, injured players and historical page entries. A roster endpoint serves the saved website snapshot only for a collected roster season; it always returns `eligibility_verified=false`. The observed-roster endpoint instead shows participation in recorded matches and is not a complete registered squad. Listed match participants are not asserted to be the starting XI.

`manual/availability.csv` is read separately without changing the database. An available/unavailable entry needs a source URL and effective date; otherwise it becomes unknown. A malformed file, duplicate key or invalid date/status fails closed to unknown. A sourced dated record is still not a live match-day fitness verification. Country-based overseas flags are only a proxy for official eligibility. There is no live injury, weather, dew or measured pitch feed.

The saved official 2026 PDF informed reviewed core planning guardrails. Its cover/introduction date discrepancy and incomplete supplementary Impact review remain documented. This is not verified match eligibility: only explicit domestic interval Impact scenarios are enabled, and country/role flags remain proxies. Availability must be confirmed for the scenario date or explicitly assumed for planning.

## Verification and refresh

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check backend tests scripts/check_backend.py
.\.venv\Scripts\python.exe scripts/check_backend.py
.\.venv\Scripts\python.exe scripts/backtest_bayesian.py
.\.venv\Scripts\python.exe scripts/check_simulation.py
```

Unit/API tests use tiny deterministic databases, with independently specified expected totals, and do not need the full raw archive. The real-data check exercises every endpoint family, reconciles matchup counts with direct delivery sums, checks coverage/rosters and verifies the database's SHA-256 before and after. It exports `outputs/backend-openapi.json` for frontend integration and `outputs/backend-checks.json` with checks and local timings. Timing samples are not a load test or production SLA. The pinned Starlette TestClient currently emits an HTTPX deprecation warning; tests pass and the production server does not use TestClient.

Stop the API before rebuilding/replacing the dataset, run the existing data validation pipeline, then restart and rerun the backend checks. The application does not support hot replacement of the database/catalog or a scheduled live refresh yet.

## Next backend work

The optional `calibrated_forecast` candidate remains separate from raw delivery posteriors; `use_delivery_calibration` still defaults false. Overlapping XI candidate sampling intervals trigger a surrogate-utility fallback rather than a noisy win-estimate winner.

Version 0.5 adds actual sampled legal-event evidence counts alongside prepared-context counts. The fractions have different denominators and must not be interchanged. Match innings summaries now expose p05/p95 quantiles, score standard deviations and Monte Carlo standard errors for the simulated mean. These describe the model's simulations, not historically guaranteed accuracy.

Historical evaluation runs offline through `scripts/backtest_matches.py`, not a new expensive HTTP endpoint. Its anonymous population forecasts and observed-participant-pool diagnostics have different information scopes; neither establishes historical XI optimization benefit. See the [full-match evaluation guide](full-match-backtesting.md) and [reliability report](reliability.md). The public roster/season/eligibility contract remains unchanged.

The delivery model, uninterrupted match simulator and constrained surrogate XI optimizer are implemented. Next work includes held-out match-level calibration, fitted state/form effects, time-valid roster/attribute/availability evidence, broader Impact-rule verification/optimization and frontend integration. Legal-delivery backtest results do not validate match-win forecasts, and proxy-optimal selection is not globally win-optimal selection.
